# V1-M02 data foundation

25 October 2026 schema V14: added nullable immutable AI-confirmation provenance to meal events and sync payloads. Existing manual meals remain valid, and migration evidence covers earlier database versions. Provenance stores request/schema/prompt/model versions, confirmation timing and accepted catalog matches; deterministic catalog calculations remain the nutrition source of truth.

21 October 2026 reactive sync-status projection: added an owner-bound, payload-free Drift aggregate exposing pending count, failed count and oldest queued timestamp for future offline banners, sync indicators and sign-out warnings. Its stream reacts to atomic commits, recorded failures and acknowledgements while rejecting cross-account access. Three projection tests pass alongside ten durable-store/upload tests, and scoped analysis is clean. No UI is wired yet; user-facing wording and manual retry actions belong to the later dashboard/account modules.

21 October 2026 production schema V2: added explicit indexes for owner-ordered outbox uploads, typed pending-entity conflict checks and owner/type/tombstone record reads. The database now has a versioned V1-to-V2 migration rather than relying only on fresh schema creation. A file-backed migration fixture proves that an existing health record, retry count/error, and pull cursor survive while all three indexes and `user_version = 2` are installed. Fresh-schema, transactional, durable adapter and encrypted reopen tests also pass (12 focused tests total); scoped analysis is clean. Android query-plan/performance evidence remains deferred.

21 October 2026 platform key-vault adapter: added `flutter_secure_storage` 11.2.0 behind a testable secure-value boundary, using its current Android default RSA-OAEP/AES-GCM protected storage and an app-specific namespace. Database keys are Base64URL encoded, account identifiers are SHA-256 hashed before becoming storage names, concurrent creation is coalesced within the application process, deletion is owner-specific, and malformed values trigger recovery rather than replacement. Nine focused vault/resolver/database tests pass and scoped analysis is clean. Device/backup behavior, cross-process creation and Android Keystore verification remain pending under the explicit device-testing deferral; the browser preview must not be treated as production key custody.

21 October 2026 durable account-cleanup boundary: `AccountDatabaseService` now reads the real owner-scoped Drift outbox before local cleanup. Pending operations block deletion with the encrypted database file and key preserved; an empty queue allows the service to close the database, remove the account file and then delete its vault key. A composition adapter connects this same boundary to the still-distinct Sign Out, Clear Local Data and Delete Account contracts. Sixteen focused account/key/database tests pass and scoped analysis is clean. The safety guarantee requires all database consumers to honor the service lifecycle; production authentication, platform vault implementation, cloud deletion and UI wiring remain pending.

21 October 2026 durable upload-attempt metadata: upload failures now update the same owner-scoped outbox operation with an incremented attempt count and a privacy-safe categorical error code. Drift performs the read/increment/write in a transaction; memory parity supports coordinator tests. Transport, authentication, conflict, invalid-receipt and unexpected failures are recorded without persisting raw exception text. Thirty focused sync/Drift tests pass and scoped analysis is clean. Successful acknowledgement removes the outbox row. Future production diagnostics still need retention/redaction review, and background scheduling plus live transport remain pending.

21 October 2026 sync execution guard: added single-flight execution so connectivity, foreground and manual triggers share one active synchronization cycle rather than racing the account database. Only typed upload transport failures retry, using bounded half-to-full-jitter backoff and a configurable three-attempt default; conflicts, authentication failures and invalid data stop immediately. Tests cover trigger coalescing, retry success, exhausted budgets, non-retryable outcomes and invalid configuration. Twenty-six focused sync/Drift tests pass and scoped analysis is clean. The delay is process-local: background scheduling, connectivity integration, persisted attempt/error metadata and production lifecycle wiring remain pending.

21 October 2026 bounded sync-cycle orchestration: added an upload-first synchronization coordinator that only begins pulling after all pending uploads are acknowledged. It maps upload/auth/conflict/receipt and pull/apply/conflict failures into explicit stop reasons, retains blocking identifiers, accumulates applied counts and caps server pagination at 20 pages by default. Integration tests prove ordering, no pull after a retryable upload failure and termination of an unbounded pagination response. Twenty-one focused sync/Drift tests pass and scoped analysis is clean. Connectivity-trigger scheduling, mutual exclusion, persisted retry attempts, live transport/authentication and background execution remain pending.

21 October 2026 durable pull/cursor adapter: added an owner-bound Drift implementation of `PullApplyStore`. Remote changes now include entity type, and every page applies typed records, tombstones and its cursor in one database transaction. A pending outbox operation for the same typed entity blocks the whole page; malformed/non-increasing changes and stale cursors roll back all page writes. Twelve focused pull/local-store tests pass and scoped analysis is clean. Live authenticated transport, pagination scheduling, explicit conflict-resolution UX, server timestamps supplied by the backend and deferred Android testing remain pending.

21 October 2026 durable sync-outbox adapter: added an owner-bound Drift implementation of `LocalChangeStore`. Entity type is now part of the sync contract and local identity, preventing equal IDs from colliding across meals, weights and future record types. Record revision and upload operation are written in one transaction; replay is idempotent, changed operation reuse and stale revisions are rejected, pending changes have deterministic order, and acknowledgements are owner-scoped. Twelve focused memory/Drift/upload tests pass and scoped analysis is clean. This is not yet wired to the application session or a live transport; encrypted account database lifecycle, backend receipts, durable pull/conflict handling and deferred Android testing remain required.

Drift profile adapter: added an owner-bound `ProfileRepository` implementation using the versioned codec. Each save commits the profile revision and matching outbox entry together; local clearing refuses pending profile operations. SQLite tests cover round-trip recovery, revision increments, outbox creation, owner rejection and pending-data protection. Authentication wiring and secure platform key storage remain pending; the preview still does not persist profiles.

Account database service: connects account-specific file resolution, key recovery and encrypted schema opening. Reuses the active account handle, rejects overlapping operations and requires closing before account switching. Windows integration testing confirms distinct files and preservation of an existing database when its key is missing. The vault used in tests is memory-only; Android protected storage and authentication/UI wiring remain pending. Account filenames encode identifiers and are not a privacy boundary.

Encrypted opener: added native `openEncryptedDatabase` and the sqlite3mc build hook. The opener checks cipher availability, requires a 32-byte key, forces schema initialization/key verification before returning and closes on failure without fallback. A Windows test using the generated app schema passes cursor persistence across reopen and wrong-key rejection. Platform secure storage, account-path resolution, lifecycle serialization and UI wiring remain pending; this factory is not called by the preview.

Key-custody boundary: `AccountKeyResolver` creates 32-byte random keys only for new account databases, reuses stored keys, and requires recovery when an existing database has no key or a stored key is malformed. Three tests pass using a fake vault. The platform vault must implement atomic create-if-absent and protected storage; the opener must serialize creation and determine actual file existence. Android Keystore integration remains pending. No production persistence is enabled by this slice.

21 October 2026 production-schema start: added Drift-generated owner-partitioned `local_records`, `sync_outbox_entries`, and `sync_cursors` tables with schema/revision fields, tombstones, client/server timestamps, retry metadata, and composite account keys. Root generation excludes isolated tool packages through `build.yaml`. In-memory SQLite schema tests verify account partitioning and rollback of a record/outbox/cursor transaction. Scoped analysis and the release web build pass. No production database opener exists yet, so the app cannot accidentally create a plaintext health store; encrypted connection and key custody remain the next gate.

21 October 2026 account-data operation separation: added distinct `ClearLocalDataUseCase` and `DeleteAccountUseCase`. Clear Local Data preserves the authenticated session and blocks when changes are pending. Delete Account requires explicit confirmation, blocks pending records, requires durable cloud acceptance before local cleanup, and clears the session only after cleanup succeeds. A race discovered after cloud acceptance produces a recoverable `localCleanupPending` state instead of destroying data. Five focused tests pass alongside the existing sign-out/profile tests. Production deletion requests must be idempotent and resumable; no UI or backend is connected.

21 October 2026 pull-conflict guard: a server page now stops with the exact entity key when that entity has an unsynchronized local edit. Neither earlier changes in the same page nor the cursor are committed, so the server version cannot silently overwrite the local version. Clearing the synthetic pending marker allows the unchanged page to apply. Five pull tests and nine upload/outbox tests pass. The memory adapter's marker is test scaffolding; the future Drift transaction must derive conflicts from the durable outbox and preserve both versions for explicit domain-specific resolution.

21 October 2026 pull/cursor slice: added a one-page authenticated pull coordinator plus an atomic memory apply adapter. It validates page owner, request cursor, next cursor, entity IDs and positive server revisions before apply. A page failure preserves every prior record and the old cursor; tombstones remain stored as deletion records rather than disappearing. Four pull tests pass alongside nine upload/outbox tests. This remains fake-transport, single-isolate evidence: there is no durable cursor, encrypted Drift adapter, pending-local-change merge policy, pagination scheduler or live backend.

21 October 2026 retry/conflict refinement: upload results now identify the blocked operation. Only an explicitly typed transport failure is retryable; auth failures, conflicts, invalid receipts and unexpected exceptions retain the operation but do not enter automatic retry. A bounded half-to-full-jitter exponential delay policy is available to a future scheduler. Six coordinator tests pass. No retry scheduler, conflict resolution UI, or live server is connected.

21 October 2026 upload orchestration slice: added `SyncUploadCoordinator` behind the authenticated-owner session, local outbox, and transport interfaces. It uploads sequentially and acknowledges only a matching owner/operation receipt with a positive server revision; conflict, transport failure, invalid receipt, or absent session leave unsent operations pending. Four coordinator tests pass alongside the local-store and profile-boundary tests. This is fake-transport evidence only: no network adapter, server authentication, pull cursor, retry schedule, durable acknowledgement, or real account session exists yet.

21 October 2026 app-side sync contract: added `LocalChangeStore` and a single-isolate memory adapter. A synthetic local record and outbox operation appear together; stale revisions and invalid payloads leave both unchanged; same-operation replay is idempotent; altered replay is rejected; owner reads and acknowledgements are isolated. Three tests and scoped analysis pass. This is a development adapter only: it is not durable, encrypted, network-connected, or crash-atomic. The future Drift adapter must use one database transaction and only acknowledge after a verified server response.

21 October 2026 owner-boundary refinement: profile creation no longer accepts a caller-supplied owner string. It obtains a stable UID through an `AuthenticatedOwnerSession` port and refuses writes without one. Tests cover unauthenticated calls and account switching without cross-owner overwrite. The fake session is test-only; a real auth adapter must hold the UID stable across the awaited write and still enforce server-side ownership. This does not add production authentication.

21 October 2026 profile-creation boundary: added `CreateProfileUseCase`, which rejects missing adult confirmation, ages below 18 or above 100, and empty owner IDs before any repository write. Unit tests confirm rejection causes no write and a confirmed 18-year-old profile is owner-isolated. This use case is not wired into the preview and does not authenticate its caller: the production auth adapter must supply a verified UID and route every account-creation write through this boundary. Server-side eligibility enforcement and privacy/legal review remain pending.

21 October 2026 adult eligibility slice: biometrics now requires an explicit 18+ confirmation before advancing. Changing the selected age resets that confirmation; an under-18 value cannot be confirmed. Adult metabolic estimates are disabled until confirmed. The final plan-claim entry point also redirects an unconfirmed user to biometrics. Controller and full onboarding-flow tests pass. This is self-attestation for preview, not identity-document verification or production account enforcement; the future auth boundary must recheck eligibility before account creation.

21 October 2026 sign-out safety slice: added an account-domain coordinator with an explicit pending-record guard. Offline pending changes block sign-out; online pending changes require an explicit sync-first choice. The storage port must recheck pending changes atomically with local cleanup to prevent a last-moment edit from being lost. Session clearing occurs only after successful local cleanup. Four domain tests pass, including sync failure and a simulated edit between inspection and clearing. This is not wired to UI or production auth/storage; no real sign-out is claimed. Clear Local Data and Delete Account remain separate future use cases.
