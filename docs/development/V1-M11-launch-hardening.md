28 October 2026 bounded trusted endpoint configuration: every compile-time consumer/admin/account/sync/billing/AI backend URL now crosses one testable parser before composition. It accepts only bounded HTTPS endpoints with a non-empty host and usable port, and rejects credentials, query strings, fragments, port zero and values over 2048 characters. Focused evidence covers safe trimming and each unsafe structure; existing gateway validators remain a second defense at transport construction.

28 October 2026 Firebase configuration identity validation: required and optional compile-time Firebase values are now trimmed, bounded to 512 characters and reject whitespace/control-character injection before SDK initialization. Focused evidence rejects malformed, oversized and control-bearing configuration before cloud or private-storage startup.

28 October 2026 environment-and-project storage isolation: trusted FlutterFire startup now includes the exact application environment as well as Firebase project ID in the hashed local-storage scope. Development, staging and production therefore remain isolated even when a Firebase project is temporarily shared. Existing project-only and original unscoped encrypted databases and protected-key aliases migrate losslessly; conflicting legacy aliases fail closed without deleting either candidate. Focused evidence verifies environment separation, database/cursor preservation, key migration and ambiguity recovery.

28 October 2026 fail-closed environment selection: compile-time `APP_ENV` parsing now accepts only an omitted/local default or the exact `development`, `staging` and `production` values. Focused parsing and existing release-consumer configuration tests preserve the explicit production-only release boundary.
