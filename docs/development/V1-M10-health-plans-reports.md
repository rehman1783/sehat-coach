# V1-M10 health plans and reports tracker

24 October 2026 local text-document selection: integrated Flutter's maintained `file_selector` 1.1.0 plugin behind a testable document-picker boundary. Users in Paste document mode can choose `.txt` or `.md`; the app accepts only non-empty, strict UTF-8 content up to 1 MB, strips null characters, fills the title/text draft and requires review plus the existing structured meal fields before saving. Selection and decoding occur locally, cancellation writes nothing, and unsupported/PDF/binary/oversized content is rejected without creating a plan. Static analysis is clean and all 39 focused tests pass. Web behavior is locally available; Android picker verification remains pending by owner direction, and PDF extraction is deliberately not claimed.

24 October 2026 reminder preference experience: added a per-plan settings sheet with an explicit enable switch, seven weekday controls, local-time picker and device timezone/UTC-offset display. New settings begin disabled; users must turn them on and retain at least one day. Turning a preference off saves an inactive schedule. The plan card reflects the saved state, concurrent saves are prevented, and copy repeatedly distinguishes the encrypted preference from native notification delivery. Static analysis is clean and all 36 focused tests pass. OS permission, alarm scheduling and Android delivery verification remain pending device testing.

24 October 2026 reminder preference foundation: added opt-in per-plan reminder settings with local minute-of-day, ISO weekdays, timezone identity and UTC update evidence. Disabled settings may have no selected days; enabled settings require at least one day and reject invalid times/days. Preferences are stored in the owner-bound encrypted generic record layer and every update atomically stages a sync operation. Saving verifies that the referenced plan exists and cross-account access fails. No notification permission is requested and no OS alarm is scheduled in this slice; native delivery remains pending Android/device review. Static analysis is clean and all 35 focused tests pass.

24 October 2026 controlled adherence export: added an explicit review-before-copy flow for the selected 7/30/90-day report. The versioned JSON contains the plan title/authorship, reporting interval, neutral counts and active event facts, while excluding account identity and original plan text. Private notes are off by default and appear in both the preview and copied payload only after a separate checkbox opt-in. The export includes a non-diagnostic notice and is never automatically shared. Static analysis is clean and all 32 focused tests pass. Native document import review and reminder controls remain pending.

24 October 2026 user-controlled adherence ranges: expanded the neutral adherence summary with per-plan 7-, 30- and 90-day selectors. Each selection recalculates locally from the active encrypted check-in history using the existing precise UTC interval rules; unsupported ranges are rejected. The selector remains available when the chosen window has zero events, so older history is still discoverable. No report is shared, uploaded, scored or clinically interpreted by this UI. Static analysis is clean and all 14 affected controller/domain/correction/persistence tests pass. Controlled export and native document import review remain pending.

24 October 2026 adherence correction experience: added a Correct action beside the latest saved check-in. The modal pre-fills the current outcome and private note, clearly explains that the earlier version remains in audit history, and creates an immutable correction rather than editing in place. The GetX controller prevents concurrent writes, handles stale correction targets separately, replaces only the visible active event and immediately refreshes the neutral seven-day counts. Authenticated composition shares the same owner-bound encrypted repository for logging, correction and loading. Static analysis is clean and all 29 focused tests pass. Longer-range reports and controlled exports remain pending.

24 October 2026 adherence corrections and audit history: added immutable correction events that supersede a currently active check-in without deleting or overwriting it. A correction retains the original occurrence time, timezone, plan, instruction and effective plan revision while recording the corrected outcome/note, a new recording time and an incremented revision. Repository validation rejects stale, cross-instruction and incorrectly sequenced corrections. Normal history and summaries expose only active events; a separate owner-scoped audit query preserves the full chain. Authenticated composition exposes the correction use case. Static analysis is clean and all 28 focused tests pass. Correction UI, longer-range reports and exports remain pending.

24 October 2026 neutral adherence insights: added a local seven-day summary that filters check-ins by a precise UTC half-open interval and reports Completed, Partial and Skipped counts. Empty intervals safely return zero proportions. Saved-plan cards now show the three counts with explicit wording that the result is factual history rather than a health score; no streak, shame, diagnosis or clinical interpretation is calculated. Static analysis is clean and all 26 focused health-plan and composition tests pass. Corrections, longer-range reports and user-controlled export remain pending.

24 October 2026 adherence check-in experience: extended the GetX health-plan controller and saved-plan cards with a responsive meal check-in bottom sheet. Users can record Completed, Partly completed or Skipped, add an optional private note, and see the saved count and latest neutral outcome. The controller reloads encrypted history with saved plans, prevents concurrent submissions, and reports failures without changing plan content. 24 October 2026 adherence event foundation: added neutral completed, partially-completed and skipped check-ins tied to an exact plan, instruction and effective revision. Logging verifies the original exists and the instruction remains active in the latest approved revision, captures UTC occurrence/recording time with the user's timezone offset, trims and limits optional private notes, and never changes the original or a revision. Events persist as immutable owner-scoped encrypted records with atomic outbox staging; cross-account writes fail before persistence. Authenticated composition exposes the logger. 24 October 2026 exact health-plan revisions: added auditable add, replace and remove instruction changes that produce a separate numbered revision while preserving the captured original byte-for-byte. Application validates the approved proposal, plan identity, exact revision sequence, duplicate targets and instruction existence; it rejects empty plans and stale revisions. Revisions persist through the existing owner-bound encrypted record/outbox transaction, and authenticated composition now exposes the revision saver. Original plans, approvals and revisions remain separate immutable records. Clinically consequential activation remains gated by the existing explicit user and approved professional-review requirements. 24 October 2026 health-plan capture and list experience: added a responsive GetX screen/controller for manual plan entry and pasted document text. Users enter the original text plus a structured first meal instruction and may state that a clinician provided it; the saved authorship remains explicitly user-reported and not independently verified. Pasted document content receives a deterministic SHA-256 digest before encrypted persistence. Saved originals load newest-first through a new owner-scoped generic-record query, retain precedence wording and display no automatic medical recommendation. Draft fields reset only after a successful create. Authenticated composition and an optional Home entry are ready; the button remains absent without a verified account feature factory. Static analysis is clean and all 23 affected domain, persistence, controller, generic-store and file-backed composition tests pass. Native document picker/permission review, richer multi-meal editing, exact proposal diffs, adherence and reports remain pending.

24 October 2026 encrypted health-plan persistence and sync staging: added an owner-bound repository over the existing encrypted generic-record/outbox transaction layer, avoiding a new schema migration. An original plan is create-once and cannot be replaced; imported/manual provenance, original text/digest, instructions and verification evidence round-trip together. Approved change records use a separate entity and operation, require the referenced original to exist, remain immutable after creation and never mutate the original payload. Authenticated composition resolves the owner from the stable session and binds both repositories to that owner's encrypted Drift database. Cross-owner operations fail before writes; record and deterministic outbox staging commit atomically. Static analysis is clean and all 12 focused domain, repository and file-backed composition tests pass. Plan list/query UI, import capture, proposal diff/application and live synchronization remain pending.

24 October 2026 health-plan provenance and precedence foundation: added immutable domain records for manually entered and imported meal plans, including original text, capture method, UTC timestamp, structured meal instructions and a required document digest for imports. Authorship distinguishes user-created, user-reported clinician-provided and independently verified clinician-provided plans; only the verified state can carry reviewer/evidence metadata, so a user's statement is never presented as verification. Any active entered plan takes precedence over automatic nutrition targets. Proposed changes retain origin, summary, rationale, timestamp and clinical-significance status; every proposal requires explicit user approval, while clinically significant changes additionally require approved professional-review evidence. The approval object does not replace or mutate the original plan. Static analysis is clean and all five focused provenance, precedence and approval tests pass. Encrypted persistence/import UI, exact diff/version application, adherence, reporting and qualified review policy remain pending.

No treatment, medication change, automatic medical-plan revision or clinician-verification claim was activated by this slice.
