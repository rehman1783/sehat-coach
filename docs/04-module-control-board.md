## Genuine pre-development dependencies

The approved onboarding follow-through is tracked in [development/onboarding-next-steps.md](development/onboarding-next-steps.md). The authenticated durable-profile boundary and accessibility verification are implemented locally; trusted provider/startup injection, mobile verification, and release evidence remain outstanding. The current public handoff stays explicitly preview-only until trusted authentication is configured.

Only the following block their associated work; finalized product decisions should not be reopened:

1. Align the local/CI Flutter SDK with Dart `^3.13.3`, or explicitly approve a different constraint.
2. Assign an owner for privacy/legal artifacts and create non-production cloud project identifiers before real cloud authentication.
3. Assign a qualified reviewer before activating calorie floors, goal-pace limits, exclusions, or clinically consequential AI language.
4. Select licensed/provenanced food, nutrition, and grocery price sources before catalog/price publication.
5. Decide whether portable encrypted export is required for offline sign-out. Until then, the safe default is to block sign-out when unsynced records cannot be protected.

## First implementation slice

V1-M01 should be one bounded pull request/change set. It must not add Firebase, AI, billing, or new feature screens. Its purpose is to make every later increment reproducible and reviewable.
